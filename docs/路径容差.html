路径容差：按公里，不按路口

惰性容差原来是「每跳 0.15 分钟」。改成「每公里 0.6 分钟」之后，同一个体感在 250 m 的支路和 10 km 的快速路上是同一个尺度。

1 · 老口径的两个毛病

容差的作用是：只有当另一条路明显更短时才换父弧。人不会为 0.01 分钟改走另一条路，而这个「随便换」正是 MSA 在均衡附近来回翻的根源。问题出在「每跳给固定分钟数」这个写法上。

毛病一：容差随地图切分变化。每跳 0.15 分钟，20 跳的行程就攒到 3 分钟 —— 但「20 跳」不是路程，是这张地图把这条路切成了多少个路口。同一段 5 km 的路，切成 10 段和切成 40 段，容差差 4 倍。路网数据一加密，模型行为就变了，这不是模型该有的自由度。
毛病二：同样 1 分钟在不同长度上意思不同。1 km 的路从 15 分钟变 16 分钟，多数人会考虑换路；10 km 的路从 15 分钟变 20 分钟，没人动。前者是「这条路堵了」，后者只是「这一趟多耗了点」。差的不是分钟数，是分摊到每一公里的分钟数。

2 · 两条体感定出 0.6

路口到路口的长度本来就在路网里（arcKm），不需要估计。于是容差直接写成 分钟/公里，按用户给的两条体感来定系数：

同样多 1 分钟，短路段是「慢下来了」，长路段只是「路上多耗一点」。容差带的宽度该跟距离成比例。

3 · 怎么实现

树里除了 dist，再带一份 tolA（到这个节点为止攒下的容差）。每跳的容差 = routeTolKm × 这条弧的长度，累加到父节点上；只有新路径短出的量超过自己这条路径攒下的容差，才允许改父弧。

// js/sim.js · roadTree
const tolKm = CFG.road.routeTolKm, tol0 = CFG.road.routeTol;

// 起点连接的接驳腿也算一份
tolA[v] = tol0 + tolKm * km[k];

// 松弛
const nd = du + time[a];
const ta = tolA[u] + tol0 + tolKm * arcKm[a];   // 这一跳的带，累加
if (nd < dist[v] - ta) {
  dist[v] = nd; dkm[v] = dkm[u] + arcKm[a]; pred[v] = a; tolA[v] = ta;
}

为什么拿「候选路径自己的带」去比：一条绕远的候选路，路程更长，带也更宽 —— 它必须省出更多分钟才划算。反过来，短路径的带很窄，只要有一点便宜就会被采纳。两个方向都偏向短路径，正是想要的。

副作用：dist 仍然是「沿所选路径的真实时间累加」，只是不保证是最小值 —— skim 不会凭空变出一个不存在的时间，月末预建树、跨月重放的前提（同一组弧、同一组时间）也不受影响。

4 · 验证：换了单位，没换标定

三个口径在 gz2 上各推 3 个月，看第 3 个月的结果。严格 = 容差 0；旧 = 0.15 分钟/跳；新 = 0.6 分钟/公里。

A为什么 0.45 / 0.75 / 1.2 三个值的差别不到 0.01%

近均衡时，备选路径之间的时间差本来就只有零点几分钟；容差带一旦超过这个量级，可选集合就饱和了 —— 再放宽也只是在几条几乎一样长的路之间换选择。所以这个系数由体感定，不由性能定。这也解释了老口径里 0.3 之后反号率就饱和在 13% 附近的现象。

一个没采纳的推测

同样的「按距离不按比例」逻辑，本来也可以套在懒分配判定上（「这一段的弧时变化是否超过 0.45 × 弧长」才算这条路变了）。实现了、跑了、没有收益：gz2 月步进 4.73 s vs 4.74 s。用 tools/lazy-gate.mjs 看门槛的实际计数就明白为什么 ——

卡住的不是「单条弧算不算变了」，而是一次全量分配之后有 8% 的弧都动了，远超 2% 的上限。改单条弧的口径只能在 337 → 302 之间挪，跨不过 294。所以这个开关留着但关着（lazyTolKm: 0）。

顺带定位到剩下的那 2.5 秒。月步进里 后续 cycle（重建树） 占 2.53 s（53%），而 后续 cycle（懒分配） 只占 0.59 s —— 4 轮里通常有 2 轮仍在全量建树。要动它得改 2% 这个上限本身（或接受更旧的树），不是改容差口径。

5 · 风险与边界

  • 整趟的带 = 0.6 × 行程公里数。gz2 的行程里程中位数是 50 km，也就是一条 50 km 的行程最多容忍 30 分钟的绕远。实测这条带几乎不绑紧（相对严格最短路只有 +1.2% 车时），但要记住这是「上限」不是「均值」。
  • 容差按长度给，不按时间给，所以严重拥堵时（同样长度、时间翻倍）带不会跟着放大 —— 这是刻意的：堵车时人更容易换路，不是更不愿意。
  • routeTol: 0 保留了「每跳基础容差」的口子（配 routeTolKm 一起用），但默认不用：基础容差等于又回到「跟跳数有关」。
